OpenMAIC has three configuration sources, and each has one job:

| Source | Written by | Holds | Takes effect |
| --- | --- | --- | --- |
| `openmaic.yml` | The operator | Providers, slot assignments and policy for AI models | At startup (restart to apply) |
| Settings in the browser | Each user | Providers, keys and model choices kept in that browser and sent with each request; they apply to the slots `openmaic.yml` leaves unassigned | Immediately |
| Environment variables (`.env.local`, a container secret) | The operator | Secrets that `openmaic.yml` references, and every other server option | At startup |

Every environment variable is optional except `DATABASE_URL` (see [Deployment](./deployment.mdx)). See [`.env.example`](https://github.com/THU-MAIC/OpenMAIC/blob/main/.env.example) for all of them, [`openmaic.example.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/main/openmaic.example.yml) for a model configuration to start from, and [Supported models](./supported-models.mdx) for preset and model IDs.

Earlier releases configured models only through provider environment variables, `server-providers.yml`, `DEFAULT_MODEL` and `MODEL_ROUTES`. Those still work for now, with the exception of `MODEL_ROUTES`, and are deprecated; see [Migrating from the legacy configuration](#migrating-from-the-legacy-configuration).

## Models and providers

### Concepts

- **Provider**: an account the server can call, such as an OpenAI key, a MiniMax token plan or a self-hosted OpenAI-compatible server. Each provider has an id you choose and a **preset** that says which vendor it is and which capabilities it covers.
- **Slot**: a use of AI in the product, such as the course outline, slide content, text to speech or web search. Slots form one tree per capability; a slot without an assignment follows its parent.
- **Assignment**: which provider and model a slot uses (`provider:model`), optionally with call parameters and a fallback model, or `null` to turn the slot off.

A slot assigned in `openmaic.yml`, or set to `null` there, decides for every user. A slot it leaves unassigned uses the provider, key and model each user picked in the browser settings.

### openmaic.yml

The server reads `openmaic.yml` from the directory it starts in (the repository root; `/app` in the Docker image). Set `OPENMAIC_CONFIG` to use another path; a relative path is resolved against the same directory, and the file must then exist. Without the file, model choices come from each user's browser settings and, while they are still set, the [legacy variables](#migrating-from-the-legacy-configuration).

The file is read once at startup: restart the server after changing it. It is validated completely before the server starts. An unset `${VAR}`, an unknown preset or slot, a reference to a provider that is not declared, or a provider that does not offer a slot's capability stops the server, and each problem is listed with its location:

```text
[boot] Invalid server configuration; the server will not start: Invalid model configuration in /app/openmaic.yml:
  - providers.openai.apiKey: environment variable OPENAI_API_KEY is not set
  - slots.course.outlines: unknown slot
```

Keep secrets out of the file itself: reference them as `${VAR}` and set the variable in the environment. Values that came from a variable are never printed in these messages.

### A complete example

```yaml title="openmaic.yml"
providers:
  # <provider id>: lowercase letters, digits and dashes
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}      # read from the environment at startup
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}
  openai-image:                    # the same key, used for images
    preset: openai-image
    apiKey: ${OPENAI_API_KEY}
  minimax:                         # a token plan: chat, image, video, TTS, search
    preset: minimax
    apiKey: ${MINIMAX_API_KEY}
  tavily:
    preset: tavily
    apiKey: ${TAVILY_API_KEY}
  local:                           # any OpenAI-compatible server
    preset: openai-compatible
    baseUrl: http://ollama:11434/v1
    models: [qwen3:8b]

slots:
  llm: openai:gpt-5.5              # default for every chat slot below
  course.outline:
    model: anthropic:claude-sonnet-4-6
    fallback: openai:gpt-5.4-mini  # tried once on a retryable failure
  course.content.slide:
    model: minimax:MiniMax-M3
    thinking: { enabled: false }
    fallback: minimax:MiniMax-M2.7
  classroom: local:qwen3:8b        # the model id may contain colons
  agent:
    model: openai:gpt-5.5          # needs tool calling
    api: openai-completions
  tts: minimax:speech-2.8-turbo
  image: openai-image:gpt-image-2
  webSearch: tavily                # provider only: its default model
  video: null                      # off, and locked off

policy:
  allowWorkspaceProviders: false   # the workspace settings API cannot add providers
```

With this file, every slot listed is fixed for all users, whatever their browser settings choose. A chat slot it leaves out, such as `course.agents`, follows its parent (`llm`); a capability root it leaves out, such as `asr` or `document`, stays unassigned, so each user's browser settings decide it.

### Providers

Each entry under `providers` declares one provider. The key is its id, which slots use in references: 1 to 63 lowercase letters, digits and dashes, starting with a letter or digit.

| Field | Required | Meaning |
| --- | --- | --- |
| `preset` | Yes | Which built-in preset this provider uses. See [Supported models → Presets](./supported-models.mdx#presets). |
| `apiKey` | Usually | The API key. Keyless services (local servers, Brave, SearXNG, unpdf) omit it. |
| `baseUrl` | Some presets | Endpoint to call instead of the preset's own. Required for `openai-compatible`, `azure`, `searxng` and `mineru`. |
| `models` | No | Model ids this provider offers for chat; the workspace settings API lists them as choices. For `openai-compatible` it is the only list. It does not restrict what `slots` may name. |
| `proxy` | No | HTTP proxy URL for this provider's requests. |
| `credentials` | Some presets | Key pairs for services that do not use one key. AliDocMind takes `accessKeyId` and `accessKeySecret`. |

Most presets cover one capability, following the built-in registries: the `openai` preset is chat only, and OpenAI images and speech are the `openai-image`, `openai-tts` and `openai-whisper` presets. Declare one provider per capability, and reference the same `${VAR}` when one key covers several. **Token plan presets** (`minimax`, `tokendance`, `volcengine-ark`, `kimi-coding-plan`) cover several capabilities with one key, each at the plan's own endpoint. A `baseUrl` on a provider replaces the endpoint for every capability that provider covers, so give a token plan a `baseUrl` only when all of its capabilities move with it.

Amazon Bedrock (`preset: bedrock`) signs requests with the AWS credential chain of the server (environment, profile or role) and reads the region from `BEDROCK_REGION`, `AWS_REGION` or `AWS_DEFAULT_REGION`; `apiKey` is an optional bearer token.

### Slots

| Slot | Capability | Parent | What it drives |
| --- | --- | --- | --- |
| `llm` | chat | — | The default chat model: every chat call no slot below covers, including the steps of the browserless `/api/generate-classroom` API that have no slot of their own |
| `course.research` | chat | `llm` | Rewriting the web search query while researching a course |
| `course.outline` | chat | `llm` | Scene outlines |
| `course.agents` | chat | `llm` | Teacher and classmate agent profiles |
| `course.content` | chat | `llm` | Scene content, for scene types without a slot of their own |
| `course.content.slide` | chat | `course.content` | Slide scenes |
| `course.content.quiz` | chat | `course.content` | Quiz scenes |
| `course.content.interactive` | chat | `course.content` | Interactive scenes |
| `course.content.pbl` | chat | `course.content` | Project-based learning scenes |
| `course.actions` | chat | `llm` | Scene actions (what the agents say and do on each scene) |
| `classroom` | chat | `llm` | Classroom chat, quiz grading and the project-based learning runtime |
| `agent` | chat | `llm` | The Pro workbench agent. **Requires tool calling.** Also accepts `api` and `contextWindow` |
| `agent.title` | chat | `agent` | Pro session titles |
| `tts` | tts | — | Text to speech |
| `asr` | asr | — | Speech recognition (voice input, audio and video transcripts) |
| `image` | image | — | Image generation |
| `video` | video | — | Video generation |
| `webSearch` | webSearch | — | Web search |
| `document` | document | — | The document parsing service (MinerU, MinerU Cloud, AliDocMind). The built-in PDF text extraction needs no service |

How a slot resolves:

- Resolution starts at the slot of the call and walks up to its capability root. The first assignment found wins, so a parent's assignment is the default for its whole subtree. Changing a parent changes every child without its own assignment.
- At each slot, `openmaic.yml` is consulted before the [workspace settings](#workspace-settings-api).
- When neither assigns the slot or any ancestor, the call uses what the user's browser sent with the request (see [Locks and the browser settings](#locks-and-the-browser-settings)), and after that the legacy `DEFAULT_MODEL` defaults. The Pro agent (`agent`) and browserless API calls never use browser choices.
- `null` stops the walk: the slot and every slot below it that has no assignment of its own are off.
- If none of these gives a model, the capability is unconfigured: calls fail with an error that names the slot; there is no fallback to any vendor.
- Requirements belong to the slot that declares them and are checked against the model it resolves to, assigned or inherited. `agent` requires tool calling; if the built-in catalogue says its model lacks it, the agent refuses to run instead of making do. A model the catalogue does not know is allowed. `agent.title` has no requirement, so it can use a smaller model.

### Assignments

An assignment has one of four forms:

```yaml
slots:
  llm: openai:gpt-5.5            # provider:model
  webSearch: tavily              # provider only: the provider's default model
  course.outline:                # an object with parameters
    model: openai:gpt-5.5
    fallback: anthropic:claude-sonnet-4-6
    thinking: { effort: low }
  video: null                    # off
```

The object form accepts:

| Field | Meaning |
| --- | --- |
| `model` | Required. `provider:model`, or `provider` alone outside chat slots. |
| `fallback` | A model to retry on once, in the same form. Language-model slots only; see [Fallbacks](#fallbacks). |
| `thinking` | Reasoning parameters for chat models: `enabled` (true/false), `mode` (`default`, `disabled`, `enabled`, `auto`), `effort` (`none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`), `level` (`minimal`, `low`, `medium`, `high`), `budgetTokens`, `excludeReasoningOutput`. Each provider adapter applies what its API supports. |
| `api` | `agent` only: the transport dialect, `openai-completions` (the default) or `openai-responses`. |
| `contextWindow` | `agent` only: the context window to assume for compaction, when it should be lower than the catalogue's. |

The `agent` slot must not set `thinking.effort`: its tool-calling transport cannot combine reasoning effort with function tools.

### Provider-only references

A reference without `:model` means the provider's default model: the model a token plan recommends for that capability, else the default of the built-in registry. Search and document services mostly have no model to pick, so `webSearch: tavily` or `document: mineru-cloud` is the usual form. Chat slots always name a model; `llm: openai` is refused at startup.

### Fallbacks

Fallbacks apply to language-model slots: `llm` and every slot below it. A `fallback` on a `tts`, `asr`, `image`, `video`, `webSearch` or `document` slot is refused, at startup for `openmaic.yml` and when saved through the workspace settings API.

A slot's `fallback` is tried once when a call on the primary model fails after its own retries with a retryable failure: a transient SDK error, a timeout, a network error, quota exhaustion (429), capacity (503), or empty output. Content-safety refusals and other 4xx errors never fall back. The fallback applies to both regular and streaming calls and uses the slot's `thinking` parameters.

The fallback belongs to the assignment and is inherited with it: `course.content.slide` without an assignment of its own uses the model and the fallback of `course.content`. A slot with a requirement does not retry on a fallback that fails it.

### Turning a capability off

Write `null` on its slot. `video: null` turns video generation off for every workspace and locks it off; `course.content.pbl: null` turns off project-based learning scene generation while the rest of `course.content` keeps working. A call on a slot that is off fails immediately, and the media routes answer `403` instead of choosing another vendor.

### Locks and the browser settings

Everything written under `slots` in `openmaic.yml` is **locked**: it decides for every user, and what a user picks for that slot in the browser settings has no effect. A written slot also covers every slot below it that has no assignment of its own, so `llm` alone fixes every chat call, including the per-step models of the browser's Course Model Config. To leave a use open, assign only the slots that should be fixed and not their ancestors.

Each user configures models in the browser (**Settings**), and the browser sends those choices, including keys, with each request:

- **Token Plan**: connect a token plan with one key; it fills the providers of the capabilities the plan covers.
- **Model Services**: one tab per capability (LLM, Image Generation, Video Generation, Text-to-Speech, Speech Recognition, Document Parsing, Web Search) to add keys, custom endpoints and models, and to pick the provider for that capability.
- **Course Model Config**: the model for each generation step, on top of the main model.

These settings and keys stay in the browser; the server does not store them. The browser lists providers configured with the legacy variables or `server-providers.yml` as server-configured, but not the providers of `openmaic.yml`, and it does not mark locked slots: a slot the deployment assigns simply overrides the browser's choice.

### Workspace settings API

The server also keeps a model configuration per workspace (`/api/model-config`), with the same shape as `openmaic.yml` minus `policy`; the web app has no screen for it. Its assignments rank after `openmaic.yml` and before the browser's choices. A workspace is an owner in the sense of the [persistence documentation](./deployment.mdx#server-side-persistence-postgresql): with the default Docker Compose setup (single-user mode) there is one workspace, and in a multi-user deployment each signed-in account has its own.

### Policy

```yaml
policy:
  allowWorkspaceProviders: false
```

`allowWorkspaceProviders` (default `true`) decides whether the workspace settings API may add providers; with `false`, providers a workspace added before are not used either. It does not affect the keys users enter in the browser settings: to fix what a slot uses, assign it in `openmaic.yml`.

### Secrets and OPENMAIC_SECRET_KEY

- Keys in `openmaic.yml` come from the environment through `${VAR}`. They are never stored in the database and never sent to the browser.
- Keys saved through the workspace settings API are stored in the database, encrypted with AES-256-GCM under the instance secret `OPENMAIC_SECRET_KEY`. Keys entered in the browser settings stay in that browser and are sent with each request; the server does not store them.
- When `OPENMAIC_SECRET_KEY` is unset, the server creates a random secret on first use in `data/instance-secret.key` (inside the `openmaic-data` volume with Docker Compose) and uses it from then on.

Keep the secret with the database backups: keys saved under a lost or changed secret cannot be read and have to be entered again (the workspace settings API marks them). Set `OPENMAIC_SECRET_KEY` explicitly when more than one instance shares the database, or on hosts without a persistent data directory such as Vercel; any string works, for example the output of `openssl rand -base64 32`.

```bash
OPENMAIC_SECRET_KEY=...        # instance secret for keys saved through the workspace settings API
OPENMAIC_CONFIG=/etc/openmaic/openmaic.yml   # optional: another path for openmaic.yml
```

### What the workspace settings API accepts

Providers from `openmaic.yml` can be anything the schema accepts. Providers added through the workspace settings API are more restricted, because their endpoint and key come from a user:

- Amazon Bedrock is not offered: it would sign with the server's own AWS credentials.
- No `proxy`, and no key pairs (`credentials`): presets that authenticate with a key pair, such as AliDocMind, are deployment-only.
- A custom `baseUrl` is allowed only for presets that offer chat, and a provider with one serves chat slots only. The URL must not contain credentials, a query string or a fragment, and must resolve to a public address unless the server sets `ALLOW_LOCAL_NETWORKS=true`. Requests to it do not follow redirects.
- Local model servers (Ollama, Lemonade) must name their own endpoint rather than use the preset's `localhost` default.
- Self-hosted media, search and document services (VoxCPM2, FunASR, Lemonade speech and images, ComfyUI, SearXNG, self-hosted MinerU) run on the server's own network and are deployment-only.
- Providers the operator switched off with a legacy `<CAP>_<VENDOR>_ENABLED=false` variable are refused.
- A workspace cannot declare a provider id that `openmaic.yml` already declares.

A deployment that wants users to reach internal services declares those providers in `openmaic.yml`.

### Requests from the browser and API clients

Browserless API calls such as `/api/generate-classroom` resolve through the same slots as the web app, for the workspace of the caller; they need no keys for the slots the deployment assigns.

The browser sends its choices as request headers and body fields: `x-model`, `x-api-key`, `x-base-url`, `x-provider-type`, `x-model-routes`, `x-image-provider`, `x-image-model`, `x-video-provider` and `x-video-model`, and the equivalent body fields of the speech, search and document routes. They are honoured only while the slot they would affect has no assignment in `openmaic.yml` or the workspace settings; once it has one, the configuration wins, and a slot set to `null` refuses the request whatever it names. An endpoint sent this way is checked like any address a user types: it must resolve to a public address unless the server sets `ALLOW_LOCAL_NETWORKS=true`.

### Migrating from the legacy configuration

When `openmaic.yml` is absent, the server translates the legacy configuration at startup and logs a deprecation notice, plus a notice for each entry that could not carry over:

| Legacy setting | Becomes |
| --- | --- |
| Provider variables (`OPENAI_API_KEY`, `TTS_MINIMAX_API_KEY`, …) and `server-providers.yml` | Deployment providers. The provider id is the preset id, which is the legacy provider id except for web search MiniMax (`minimax-search`), web search Doubao (`doubao-search`) and Lemonade images (`lemonade-image`) |
| `<PREFIX>_MODELS` | The provider's `models` |
| `DEFAULT_MODEL` | The `llm` assignment, as a default (not locked) that the workspace settings and each user's browser choice override. The `agent` slot stays off, as before |
| `MODEL_FALLBACK` | The fallback of `DEFAULT_MODEL`. Without `DEFAULT_MODEL` it is dropped with a notice |
| The first configured TTS, ASR, image, video and document provider, and web search in the old priority order | The default assignment of that capability (`DEFAULT_IMAGE_PROVIDER` picks the image provider) |
| `MODEL_ROUTES` | **Not translated.** The server refuses to start (see below) |
| `<CAP>_<VENDOR>_ENABLED=false` | Still honoured: the provider stays off whatever assigns it |

When `openmaic.yml` exists, `DEFAULT_MODEL`, `MODEL_FALLBACK` and `MODEL_ROUTES` are ignored, and the provider variables and `server-providers.yml` no longer become slot assignments, with a notice. The providers they configure still serve as server-configured providers for the choices users make in the browser settings. `<CAP>_<VENDOR>_ENABLED=false` still applies; to turn a capability off for everyone, set its slot to `null` instead.

**Environment variables.** Before:

```bash
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
DEFAULT_MODEL=openai:gpt-5.5
MODEL_FALLBACK=anthropic:claude-sonnet-4-6
TTS_MINIMAX_API_KEY=...
TAVILY_API_KEY=tvly-...
```

After (the keys stay in the environment):

```yaml title="openmaic.yml"
providers:
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}
  minimax-tts:
    preset: minimax-tts
    apiKey: ${TTS_MINIMAX_API_KEY}
  tavily:
    preset: tavily
    apiKey: ${TAVILY_API_KEY}

slots:
  llm:
    model: openai:gpt-5.5
    fallback: anthropic:claude-sonnet-4-6
  tts: minimax-tts
  webSearch: tavily
```

Remove `DEFAULT_MODEL` and `MODEL_FALLBACK` afterwards. The provider variables can stay as the source of the `${VAR}` references. Unlike the translated `DEFAULT_MODEL`, the `llm` written here is locked; leave it out of `slots` to let users choose in their browser settings. And unlike the translation, `agent` now follows `llm`: write `agent: null` to keep the Pro agent off.

**server-providers.yml.** Before:

```yaml title="server-providers.yml"
providers:
  azure:
    apiKey: ...
    baseUrl: https://YOUR-RESOURCE.openai.azure.com/openai
    models: [my-deployment]
pdf:
  alidocmind:
    accessKeyId: ...
    accessKeySecret: ...
web-search:
  searxng:
    baseUrl: http://searxng:8080
```

After:

```yaml title="openmaic.yml"
providers:
  azure:
    preset: azure
    apiKey: ${AZURE_OPENAI_API_KEY}
    baseUrl: https://YOUR-RESOURCE.openai.azure.com/openai
    models: [my-deployment]
  alidocmind:
    preset: alidocmind
    credentials:
      accessKeyId: ${ALIDOCMIND_ACCESS_KEY_ID}
      accessKeySecret: ${ALIDOCMIND_ACCESS_KEY_SECRET}
  searxng:
    preset: searxng
    baseUrl: http://searxng:8080

slots:
  llm: azure:my-deployment
  document: alidocmind
  webSearch: searxng
```

Each section of `server-providers.yml` becomes providers with the matching preset (`providers` → chat presets, `tts`, `asr`, `pdf` → document, `image`, `video`, `web-search`), and `accessKeyId`/`accessKeySecret` move under `credentials`.

**MODEL_ROUTES.** A server that sets `MODEL_ROUTES` without `openmaic.yml` does not start:

```text
MODEL_ROUTES does not carry over to the model configuration: write the per-stage models as slots in openmaic.yml (or the file named by OPENMAIC_CONFIG) and remove MODEL_ROUTES
```

Per-stage routes do not map one to one onto slots, so they are not translated. Rewrite each route as the slot its stage belongs to:

| `MODEL_ROUTES` stage | Slot |
| --- | --- |
| `web-search-query-rewrite` | `course.research` |
| `scene-outlines-stream` | `course.outline` |
| `agent-profiles` | `course.agents` |
| `scene-content` | `course.content` |
| `scene-content:slide`, `:quiz`, `:interactive`, `:pbl` | `course.content.slide`, `.quiz`, `.interactive`, `.pbl` |
| `scene-actions` | `course.actions` |
| `chat-adapter`, `quiz-grade`, `pbl-v2-runtime` and its `:instructor`, `:open-task`, `:evaluate`, `:simulator` variants | `classroom` |
| `generate-classroom` | `llm` |
| `maic-agent-driver` | `agent` |
| `conversation-title` | `agent.title` |

Several stages share a slot: give the slot the one model they should use. A route's `thinking` moves to the slot's `thinking`, and a `maic-agent-driver` route's `api` and `contextWindow` move to the `agent` slot. Before:

```bash
DEFAULT_MODEL=openai:gpt-5.5
MODEL_ROUTES='{"scene-outlines-stream":"anthropic:claude-sonnet-4-6","scene-content:slide":{"model":"openai:gpt-5.4","thinking":{"effort":"low"}},"maic-agent-driver":{"model":"openai:gpt-5.5","api":"openai-completions"}}'
```

After:

```yaml title="openmaic.yml"
providers:
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}

slots:
  llm: openai:gpt-5.5
  course.outline: anthropic:claude-sonnet-4-6
  course.content.slide:
    model: openai:gpt-5.4
    thinking: { effort: low }
  agent:
    model: openai:gpt-5.5
    api: openai-completions
```

Then remove `MODEL_ROUTES`, `DEFAULT_MODEL` and `MODEL_FALLBACK`.

**Docker.** Mount the file next to the app and keep the keys in `.env.local`:

```yaml
services:
  openmaic:
    volumes:
      - ./openmaic.yml:/app/openmaic.yml:ro
```

## ACCESS_CODE — site-wide password

For shared deployments such as internal demos or classrooms, set an access code so visitors must enter a password before they can see the app:

```bash
ACCESS_CODE=your-secret-code
```

Use a long random value (at least 16 characters) — this code is the only secret guarding the deployment. The code is remembered in a signed token stored in an HTTP-only cookie for 7 days; the lifetime is enforced server-side, so visitors re-verify after it expires. Verification is rate limited only when `TRUST_PROXY_HEADERS=true` is set behind a trusted proxy that overwrites `x-forwarded-for` / `x-real-ip`: each client gets 10 attempts per 60 seconds, and a successful verification clears that client's counter. Without a trusted proxy the app cannot attribute a request to a client, so there is no throttle; rely on the length and randomness of the code. Leave it empty to disable access control.

## Feature flags

Feature flags accept `true` or `1`; unless noted otherwise, all other values are treated as disabled. `NEXT_PUBLIC_*` flags are injected into the client at build time, so changing them requires a rebuild:

```bash
# MAIC Editor (Pro mode)
NEXT_PUBLIC_MAIC_EDITOR_ENABLED=true

# Pi chat is enabled by default; uncomment the next line for legacy rollback
# NEXT_PUBLIC_PI_CHAT_ENABLED=false

# PPT and Interactive courseware references in Pi playback (build-time; editor references are separate)
NEXT_PUBLIC_COURSEWARE_REFERENCE_ENABLED=true

# Vocational education task engine (server-side flag)
OPENMAIC_ENABLE_VOCATIONAL=true

# Show the vocational education experimental switch
NEXT_PUBLIC_SHOW_VOCATIONAL_TEST_UI=true

# Show the video export entry point
NEXT_PUBLIC_ENABLE_VIDEO_EXPORT=true

# Show the experimental PPTX import entry point
NEXT_PUBLIC_ENABLE_PPTX_IMPORT=true
```

Pi chat requires model tool/function calling. If the selected model or provider does not support tool calls, set `NEXT_PUBLIC_PI_CHAT_ENABLED=false` (or `0`) and rebuild to use the legacy chat path.

With Docker Compose, `.env.local` is loaded by `env_file` at runtime, not used for build-arg interpolation. Rebuild with an explicit build-time override as below; a runtime-only change leaves the built client and server on their original chat path.

```bash
NEXT_PUBLIC_PI_CHAT_ENABLED=false docker compose up -d --build openmaic
```

PPTX import is still experimental, and its parsed output is not yet fully integrated into the classroom data flow. All `NEXT_PUBLIC_*` variables above are build-time flags. Docker deployments must also pass them as build args; setting them only as container runtime environment variables is not sufficient.

## Other server options

The following server options can also be configured with environment variables:

```bash
# Parallel scene-content generation; 0 or unset means sequential
PARALLEL_SCENE_CONCURRENCY=3

# Allow localhost and private-network addresses; self-hosted/private deployments only
ALLOW_LOCAL_NETWORKS=true

# Optional MP4 rendering service
RENDER_SERVICE_URL=http://render-service:9000

# Logging and reasoning
LOG_LEVEL=info
LOG_FORMAT=pretty
LLM_THINKING_DISABLED=false
```

## Legacy provider environment variables

These variables and `server-providers.yml` are the configuration of earlier releases. They still work when there is no `openmaic.yml` (see [Migrating from the legacy configuration](#migrating-from-the-legacy-configuration)) and are deprecated. With `openmaic.yml`, use them as the source of `${VAR}` references; the providers they configure also stay available to the browser settings as server-configured providers. `DEFAULT_MODEL` and `MODEL_FALLBACK` are covered in the migration section; `MODEL_ROUTES` is no longer read.

### LLM providers

Cloud providers generally use three environment variables: an API key, a base URL, and a model list. The API key is usually required; the base URL and model list are optional. Azure OpenAI requires a resource endpoint, while Ollama and Lemonade do not require an API key.

```bash
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=                # optional base URL override
OPENAI_MODELS=                  # optional model allowlist (comma-separated)
```

Supported provider prefixes:

| Prefix             | Provider                                      |
| ------------------ | --------------------------------------------- |
| `OPENAI_`          | OpenAI                                        |
| `AZURE_OPENAI_`    | Azure OpenAI                                  |
| `ANTHROPIC_`       | Anthropic                                     |
| `GOOGLE_`          | Google Gemini                                 |
| `DEEPSEEK_`        | DeepSeek                                      |
| `QWEN_`            | Alibaba Qwen                                  |
| `KIMI_`            | Moonshot Kimi                                 |
| `MINIMAX_`         | MiniMax (Anthropic-compatible endpoint by default) |
| `GLM_`             | Zhipu GLM                                     |
| `SILICONFLOW_`     | SiliconFlow                                   |
| `DOUBAO_`          | Doubao (ByteDance)                            |
| `OPENROUTER_`      | OpenRouter                                    |
| `GROK_`            | xAI Grok                                      |
| `TENCENT_`         | Tencent Hunyuan                               |
| `TENCENT_HUNYUAN_` | Tencent Hunyuan (alias)                       |
| `XIAOMI_`          | Xiaomi MiMo                                   |
| `MIMO_`            | Xiaomi MiMo (alias)                           |
| `OLLAMA_`          | Ollama (local)                                |
| `LEMONADE_`        | Lemonade (local)                              |

Azure OpenAI uses the deployment name as the model ID:

```bash
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_BASE_URL=https://YOUR-RESOURCE.openai.azure.com/openai
AZURE_OPENAI_MODELS=your-deployment-name
```

To connect another OpenAI-compatible LLM service, add a custom provider under **Settings → Model Services → LLM**, or declare an `openai-compatible` provider with its `baseUrl` and `models` in `openmaic.yml`.

### Local models (Ollama and Lemonade)

Ollama and Lemonade do not require an API key. Put the local service base URL in the server configuration so it passes SSRF validation:

```bash
OLLAMA_BASE_URL=http://localhost:11434/v1
# LEMONADE_BASE_URL=http://localhost:13305/v1
```

To limit available models, use `OLLAMA_MODELS` or `LEMONADE_MODELS` as a model allowlist.

### TTS providers

Server-side TTS providers use `TTS_<PROVIDER>_API_KEY` and optionally `TTS_<PROVIDER>_BASE_URL`.

```bash
# Doubao TTS (Volcengine Seed-TTS, native MP3)
TTS_DOUBAO_API_KEY=appId:accessKey
TTS_DOUBAO_BASE_URL=       # optional override

# Qwen TTS
TTS_QWEN_API_KEY=
TTS_QWEN_BASE_URL=         # optional override

# Any OpenAI-compatible TTS endpoint
TTS_OPENAI_API_KEY=
TTS_OPENAI_BASE_URL=

# VoxCPM2 (self-hosted TTS with voice cloning; see the dedicated VoxCPM2 page)
TTS_VOXCPM_BASE_URL=http://localhost:8000
```

Supported TTS prefixes include `TTS_OPENAI_`, `TTS_AZURE_`, `TTS_GLM_`, `TTS_QWEN_`, `TTS_MINIMAX_`, `TTS_DOUBAO_`, `TTS_ELEVENLABS_`, `TTS_VOXCPM_`, and `TTS_LEMONADE_`. Local Lemonade TTS and VoxCPM2 do not require an API key. Browser-native TTS requires no server configuration.

Administrators can force-disable a TTS provider on the server with `TTS_<PROVIDER>_ENABLED=false`. See the dedicated [VoxCPM2](./voxcpm.mdx) section for self-hosted TTS and voice cloning.

Users can also add a custom OpenAI-compatible TTS provider under **Settings → Model Services → Text-to-Speech** by entering its Base URL, model and voice; it is stored in that browser. To configure one for everyone, declare an `openai-tts` provider with that `baseUrl` in `openmaic.yml` and assign the `tts` slot to it.

### ASR (speech to text)

```bash
# OpenAI Whisper
ASR_OPENAI_API_KEY=
ASR_OPENAI_BASE_URL=       # optional override

# Qwen ASR
ASR_QWEN_API_KEY=
ASR_QWEN_BASE_URL=         # optional override

# Azure ASR
ASR_AZURE_API_KEY=
ASR_AZURE_BASE_URL=https://{region}.api.cognitive.microsoft.com

# FunASR (local, no key required)
ASR_FUNASR_BASE_URL=http://localhost:8000/v1

# Lemonade ASR (local, no key required)
ASR_LEMONADE_BASE_URL=http://localhost:13305/v1
```

Start the OpenAI-compatible FunASR service with `funasr-server --device cuda`. It accepts WAV uploads at `/v1/audio/transcriptions` and provides SenseVoiceSmall, Paraformer, and Fun-ASR-Nano through the model selector.

Browser-native ASR requires no server configuration.

Users can also add a custom OpenAI-compatible ASR provider under **Settings → Model Services → Speech Recognition** by entering its Base URL, model and supported languages; it is stored in that browser. To configure one for everyone, declare it in `openmaic.yml` with the `openai-whisper` preset and its `baseUrl`, and assign the `asr` slot to it:

```yaml title="openmaic.yml"
providers:
  my-asr:
    preset: openai-whisper
    apiKey: ${MY_ASR_API_KEY}
    baseUrl: https://asr.example.com/v1

slots:
  asr: my-asr:whisper-1
```

### Image generation providers

Image generation providers use `IMAGE_<PROVIDER>_API_KEY` and optionally `IMAGE_<PROVIDER>_BASE_URL`. Supported prefixes include:

`IMAGE_OPENAI_`, `IMAGE_SEEDREAM_`, `IMAGE_QWEN_IMAGE_`, `IMAGE_NANO_BANANA_`, `IMAGE_MINIMAX_`, `IMAGE_GROK_`, and `IMAGE_LEMONADE_`.

Lemonade is a local service and does not require a key:

```bash
IMAGE_LEMONADE_BASE_URL=http://localhost:13305/v1
```

ComfyUI Image does not require an API key and connects to `http://localhost:8188` by default. A user can enter the ComfyUI Base URL under **Settings → Model Services → Image Generation**; an address typed there is checked like any user endpoint, so a ComfyUI server on the host or a private network also needs `ALLOW_LOCAL_NETWORKS=true` on the server. To configure it for everyone, declare it in `openmaic.yml` and assign the `image` slot to it:

```yaml title="openmaic.yml"
providers:
  comfyui:
    preset: comfyui-image
    baseUrl: http://host.docker.internal:8188

slots:
  image: comfyui
```

Place workflow JSON exported in API format in OpenMAIC's `public/` directory. Use filenames matching `comfyui-*.json` or containing `workflow`; the settings discover these files automatically and offer them as workflows. With Docker, add the workflow before building the image or mount an individual workflow file into `/app/public/` in the container. Declared in `openmaic.yml`, a ComfyUI server on the host or a private network does not need `ALLOW_LOCAL_NETWORKS`.

### Video generation providers

Video generation providers use `VIDEO_<PROVIDER>_API_KEY` and optionally `VIDEO_<PROVIDER>_BASE_URL`. Supported prefixes include:

`VIDEO_SEEDANCE_`, `VIDEO_KLING_`, `VIDEO_VEO_`, `VIDEO_SORA_`, `VIDEO_MINIMAX_`, `VIDEO_GROK_`, and `VIDEO_HAPPYHORSE_`.

### Document and media parsing

The exact course-material formats depend on the selected parser. OpenMAIC currently supports text, PDF, Office documents, images, and some audio/video formats; supported formats and capabilities vary by provider.

```bash
# MinerU self-hosted
PDF_MINERU_BASE_URL=http://localhost:8888

# Optional backend for self-hosted MinerU
PDF_MINERU_BACKEND=pipeline

# MinerU Cloud
PDF_MINERU_CLOUD_API_KEY=
PDF_MINERU_CLOUD_BASE_URL=https://mineru.net/api/v4

# AliDocMind (uses Alibaba Cloud AccessKey, not a separate API key)
ALIDOCMIND_ACCESS_KEY_ID=
ALIDOCMIND_ACCESS_KEY_SECRET=
ALIDOCMIND_BASE_URL=       # optional override
```

`unpdf` is built into OpenMAIC and supports basic PDF parsing. For Office documents, images, and material requiring OCR, table, formula, or layout analysis, select a compatible MinerU or AliDocMind provider.

AliDocMind document parsing supports PDF, DOCX, PPTX, XLSX, and PNG, JPG/JPEG, BMP, and GIF. Audio and video material is currently supported only through AliDocMind: MP4, MOV, AVI, MKV, and WMV for video; MP3, WAV, and AAC for audio. M4A is not supported.

### Web search

Configure Tavily, Exa, Bocha, Brave, Baidu, SearXNG, or MiniMax:

```bash
TAVILY_API_KEY=
TAVILY_BASE_URL=           # optional override

EXA_API_KEY=
EXA_BASE_URL=https://api.exa.ai  # optional override

BOCHA_API_KEY=
BOCHA_BASE_URL=            # optional override

BAIDU_API_KEY=
BAIDU_BASE_URL=https://qianfan.baidubce.com  # optional override

# Self-hosted SearXNG, no API key required
SEARXNG_BASE_URL=

WEB_SEARCH_MINIMAX_API_KEY=
WEB_SEARCH_MINIMAX_BASE_URL=https://api.minimaxi.com  # optional override
```

Brave and SearXNG do not require an API key. The frontend lets users choose whether to enable search for each generation; a `webSearch: null` slot in `openmaic.yml` turns it off for everyone. Grok web search is provided through the Grok LLM search tool, not a standalone web-search provider.

### server-providers.yml

Deprecated in favour of `openmaic.yml`. When both exist, only `openmaic.yml` configures models.

In addition to environment variables, place configuration for providers registered in the code in `server-providers.yml` at the project root. The server loads it at startup, and its structure follows the environment variable categories:

```yaml title="server-providers.yml"
providers:
  openai:
    apiKey: sk-...
    baseUrl: https://api.openai.com/v1
    models:
      - gpt-5.5
  anthropic:
    apiKey: sk-ant-...

tts:
  doubao-tts:
    apiKey: appId:accessKey

asr:
  openai-whisper:
    apiKey: sk-...

pdf:
  mineru:
    baseUrl: http://localhost:8888
  alidocmind:
    accessKeyId: your-access-key-id
    accessKeySecret: your-access-key-secret

image:
  seedream:
    apiKey: ...

video:
  seedance:
    apiKey: ...

web-search:
  tavily:
    apiKey: tvly-...
  exa:
    apiKey: ...
  searxng:
    baseUrl: http://localhost:8080
```

Environment variables override matching YAML provider fields one by one. Keys must use provider IDs registered in the code, such as `openai`, `doubao-tts`, `openai-whisper`, `mineru`, `alidocmind`, `seedream`, `seedance`, `exa`, `tavily`, or `searxng`. Unknown IDs cannot register custom LLM providers here.
