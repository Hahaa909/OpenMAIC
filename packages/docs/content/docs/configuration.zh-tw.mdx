OpenMAIC 有三個設定來源，各自只負責一件事：

| 來源 | 由誰撰寫 | 內容 | 何時生效 |
| --- | --- | --- | --- |
| `openmaic.yml` | 維運人員 | AI 模型的供應商、插槽指派和政策 | 啟動時（修改後需重新啟動） |
| 瀏覽器中的設定 | 每位使用者 | 儲存在該瀏覽器中、隨每個請求傳送的供應商、key 和模型選擇；作用於 `openmaic.yml` 沒有指派的插槽 | 立即生效 |
| 環境變數（`.env.local`、容器 Secret） | 維運人員 | `openmaic.yml` 引用的金鑰，以及其他所有伺服器端選項 | 啟動時 |

除了 `DATABASE_URL`，所有環境變數都是選填（見[部署](./deployment.mdx)）。全部環境變數請見 [`.env.example`](https://github.com/THU-MAIC/OpenMAIC/blob/main/.env.example)，可以從 [`openmaic.example.yml`](https://github.com/THU-MAIC/OpenMAIC/blob/main/openmaic.example.yml) 開始撰寫模型設定，範本和模型 ID 請見[支援的模型](./supported-models.mdx)。

早期版本只能透過供應商環境變數、`server-providers.yml`、`DEFAULT_MODEL` 和 `MODEL_ROUTES` 設定模型。除了 `MODEL_ROUTES`，這些方式目前仍可使用，但已棄用，請見[從舊設定遷移](#從舊設定遷移)。

## 模型與供應商

### 基本概念

- **供應商（provider）**：伺服器端可以呼叫的一個帳號，例如一把 OpenAI key、一個 MiniMax Token Plan 或一個自架的 OpenAI 相容服務。每個供應商有一個你自訂的 ID，以及一個**範本（preset）**，說明它是哪家廠商、涵蓋哪些能力。
- **插槽（slot）**：產品中用到 AI 的一處地方，例如課程大綱、投影片內容、語音合成或網路搜尋。每種能力的插槽構成一棵樹；沒有指派的插槽沿用父插槽。
- **指派（assignment）**：插槽使用哪個供應商的哪個模型（`provider:model`），可以附帶呼叫參數和備援模型；也可以寫 `null` 關閉該插槽。

在 `openmaic.yml` 中指派（或設為 `null`）的插槽對所有使用者生效。它沒有指派的插槽，使用每位使用者在瀏覽器設定中選擇的供應商、key 和模型。

### openmaic.yml

伺服器端從啟動目錄（儲存庫根目錄；Docker 映像檔中為 `/app`）讀取 `openmaic.yml`。設定 `OPENMAIC_CONFIG` 可以改用其他路徑；相對路徑同樣以啟動目錄為基準解析，而且此時檔案必須存在。沒有該檔案時，模型選擇來自每位使用者的瀏覽器設定，以及仍在設定中的[舊版變數](#從舊設定遷移)。

該檔案只在啟動時讀取一次，修改後需要重新啟動服務。服務啟動前會完整驗證檔案：未設定的 `${VAR}`、未知的範本或插槽、引用了未宣告的供應商，或供應商不提供插槽所需的能力，都會讓服務拒絕啟動，並逐條列出問題所在的位置：

```text
[boot] Invalid server configuration; the server will not start: Invalid model configuration in /app/openmaic.yml:
  - providers.openai.apiKey: environment variable OPENAI_API_KEY is not set
  - slots.course.outlines: unknown slot
```

不要把金鑰直接寫進檔案：用 `${VAR}` 引用，並在環境變數中設定。來自環境變數的值不會出現在這些錯誤訊息中。

### 完整範例

```yaml title="openmaic.yml"
providers:
  # <供應商 ID>：小寫字母、數字和連字號
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}      # 啟動時從環境變數讀取
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}
  openai-image:                    # 同一把 key，用於圖像生成
    preset: openai-image
    apiKey: ${OPENAI_API_KEY}
  minimax:                         # Token Plan：對話、圖像、影片、TTS、搜尋
    preset: minimax
    apiKey: ${MINIMAX_API_KEY}
  tavily:
    preset: tavily
    apiKey: ${TAVILY_API_KEY}
  local:                           # 任何 OpenAI 相容服務
    preset: openai-compatible
    baseUrl: http://ollama:11434/v1
    models: [qwen3:8b]

slots:
  llm: openai:gpt-5.5              # 下方所有對話插槽的預設值
  course.outline:
    model: anthropic:claude-sonnet-4-6
    fallback: openai:gpt-5.4-mini  # 遇到可重試的失敗時改用一次
  course.content.slide:
    model: minimax:MiniMax-M3
    thinking: { enabled: false }
    fallback: minimax:MiniMax-M2.7
  classroom: local:qwen3:8b        # 模型 ID 可以包含冒號
  agent:
    model: openai:gpt-5.5          # 需要支援工具呼叫
    api: openai-completions
  tts: minimax:speech-2.8-turbo
  image: openai-image:gpt-image-2
  webSearch: tavily                # 只寫供應商：使用它的預設模型
  video: null                      # 關閉，並鎖定為關閉

policy:
  allowWorkspaceProviders: false   # 工作區設定 API 不能新增供應商
```

使用這份檔案時，列出的每個插槽對所有使用者都是固定的，不論他們的瀏覽器設定選了什麼。檔案沒寫的對話插槽（例如 `course.agents`）沿用父插槽（`llm`）；沒寫的能力根插槽（例如 `asr` 或 `document`）維持未指派，由每位使用者的瀏覽器設定決定。

### 供應商

`providers` 下的每一項宣告一個供應商。鍵名就是它的 ID，供插槽引用：1 到 63 個小寫字母、數字和連字號，以字母或數字開頭。

| 欄位 | 是否必填 | 意義 |
| --- | --- | --- |
| `preset` | 是 | 使用哪個內建範本，請見[支援的模型 → 範本](./supported-models.mdx#範本)。 |
| `apiKey` | 通常需要 | API key。不需要 key 的服務（本機服務、Brave、SearXNG、unpdf）可以省略。 |
| `baseUrl` | 部分範本需要 | 取代範本內建端點的位址。`openai-compatible`、`azure`、`searxng` 和 `mineru` 必填。 |
| `models` | 否 | 該供應商提供的對話模型 ID；工作區設定 API 會把它們列為選項。對 `openai-compatible` 來說這是唯一的清單。它不會限制 `slots` 能寫哪些模型。 |
| `proxy` | 否 | 該供應商請求使用的 HTTP 代理位址。 |
| `credentials` | 部分範本需要 | 不使用單一 key 的服務所需的金鑰對。AliDocMind 使用 `accessKeyId` 和 `accessKeySecret`。 |

大多數範本只涵蓋一種能力，與內建 registry 一一對應：`openai` 範本只有對話，OpenAI 的圖像、語音合成和語音辨識分別是 `openai-image`、`openai-tts` 和 `openai-whisper` 範本。每種能力宣告一個供應商；同一把 key 涵蓋多種能力時，引用同一個 `${VAR}` 即可。**Token Plan 範本**（`minimax`、`tokendance`、`volcengine-ark`、`kimi-coding-plan`）用一把 key 涵蓋多種能力，每種能力使用該方案自己的端點。供應商上的 `baseUrl` 會取代它涵蓋的所有能力的端點，因此只有當 Token Plan 的全部能力都一起搬移時，才為它設定 `baseUrl`。

Amazon Bedrock（`preset: bedrock`）使用伺服器端的 AWS 憑證鏈（環境變數、profile 或 role）簽署請求，區域取自 `BEDROCK_REGION`、`AWS_REGION` 或 `AWS_DEFAULT_REGION`；`apiKey` 是選填的 bearer token。

### 插槽

| 插槽 | 能力 | 父插槽 | 作用 |
| --- | --- | --- | --- |
| `llm` | chat | — | 預設對話模型：下方任何插槽都不涵蓋的對話呼叫，包括無瀏覽器 `/api/generate-classroom` API 中沒有專屬插槽的步驟 |
| `course.research` | chat | `llm` | 課程研究時改寫網路搜尋查詢 |
| `course.outline` | chat | `llm` | 場景大綱 |
| `course.agents` | chat | `llm` | 老師和同學智慧體的人設 |
| `course.content` | chat | `llm` | 場景內容（沒有專屬插槽的場景類型） |
| `course.content.slide` | chat | `course.content` | 投影片場景 |
| `course.content.quiz` | chat | `course.content` | 測驗場景 |
| `course.content.interactive` | chat | `course.content` | 互動場景 |
| `course.content.pbl` | chat | `course.content` | 專題式學習（PBL）場景 |
| `course.actions` | chat | `llm` | 場景動作（智慧體在每個場景說什麼、做什麼） |
| `classroom` | chat | `llm` | 課堂對話、測驗評分和 PBL 執行階段 |
| `agent` | chat | `llm` | Pro 工作台智慧體。**需要工具呼叫能力。** 另外支援 `api` 和 `contextWindow` |
| `agent.title` | chat | `agent` | Pro 工作階段標題 |
| `tts` | tts | — | 語音合成 |
| `asr` | asr | — | 語音辨識（語音輸入、影音逐字稿） |
| `image` | image | — | 圖像生成 |
| `video` | video | — | 影片生成 |
| `webSearch` | webSearch | — | 網路搜尋 |
| `document` | document | — | 文件解析服務（MinerU、MinerU Cloud、AliDocMind）。內建的 PDF 文字擷取不需要服務 |

插槽的解析方式：

- 從呼叫所在的插槽開始，逐層往上直到能力根插槽，遇到的第一個指派生效。因此父插槽的指派就是整棵子樹的預設值；修改父插槽，會同時改變所有沒有自己指派的子插槽。
- 在每個插槽上，先看 `openmaic.yml`，再看[工作區設定](#工作區設定-api)。
- 兩者都沒有為該插槽或其任何祖先指派時，呼叫使用使用者瀏覽器隨請求傳送的選擇（見[鎖定與瀏覽器設定](#鎖定與瀏覽器設定)），再之後是舊版的 `DEFAULT_MODEL` 預設值。Pro 智慧體（`agent`）和無瀏覽器 API 呼叫從不使用瀏覽器的選擇。
- `null` 會停止往上查找：該插槽，以及其下所有沒有自己指派的插槽，都會被關閉。
- 以上都沒有給出模型時，該能力處於未設定狀態：呼叫會報錯並指出插槽名稱，不會退回任何廠商。
- 需求（requirement）屬於宣告它的插槽，依該插槽最終解析到的模型檢查，無論是自己指派還是繼承而來。`agent` 需要支援工具呼叫；若內建模型目錄表明它的模型不支援，智慧體會拒絕執行，而不是勉強湊合。目錄中沒有的模型允許使用。`agent.title` 沒有需求，因此可以使用較小的模型。

### 指派

指派有四種寫法：

```yaml
slots:
  llm: openai:gpt-5.5            # 供應商:模型
  webSearch: tavily              # 只寫供應商：使用它的預設模型
  course.outline:                # 帶參數的物件
    model: openai:gpt-5.5
    fallback: anthropic:claude-sonnet-4-6
    thinking: { effort: low }
  video: null                    # 關閉
```

物件寫法支援以下欄位：

| 欄位 | 意義 |
| --- | --- |
| `model` | 必填。`供應商:模型`；對話以外的插槽也可以只寫 `供應商`。 |
| `fallback` | 改用一次的備援模型，寫法同上。僅適用於語言模型插槽，請見[備援模型](#備援模型)。 |
| `thinking` | 對話模型的推理參數：`enabled`（true/false）、`mode`（`default`、`disabled`、`enabled`、`auto`）、`effort`（`none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`）、`level`（`minimal`、`low`、`medium`、`high`）、`budgetTokens`、`excludeReasoningOutput`。各供應商轉接器只套用其 API 支援的部分。 |
| `api` | 僅 `agent`：傳輸協定，`openai-completions`（預設）或 `openai-responses`。 |
| `contextWindow` | 僅 `agent`：壓縮上下文時假定的視窗大小，用於比模型目錄中的值更小的情況。 |

`agent` 插槽不能設定 `thinking.effort`：它的工具呼叫傳輸無法同時使用推理強度和函式工具。

### 只寫供應商 ID 的引用

不帶 `:model` 的引用代表該供應商的預設模型：Token Plan 為該能力推薦的模型，否則是內建 registry 的預設模型。搜尋和文件服務大多沒有可選的模型，所以通常寫成 `webSearch: tavily` 或 `document: mineru-cloud`。對話插槽必須寫明模型，`llm: openai` 會在啟動時被拒絕。

### 備援模型

備援模型只適用於語言模型插槽，也就是 `llm` 及其下的所有插槽。在 `tts`、`asr`、`image`、`video`、`webSearch` 或 `document` 插槽上寫 `fallback` 會被拒絕：`openmaic.yml` 在啟動時拒絕，工作區設定 API 在儲存時拒絕。

當主模型的呼叫在自身重試之後仍以可重試的方式失敗時，會改用插槽的 `fallback` 再試一次。可重試的失敗包括：SDK 判定的暫時性錯誤、逾時、網路錯誤、額度用盡（429）、容量不足（503）或輸出為空。內容安全拒絕和其他 4xx 錯誤不會觸發備援。備援對一般呼叫和串流呼叫都有效，並沿用插槽的 `thinking` 參數。

備援模型屬於指派，隨指派一起被繼承：沒有自己指派的 `course.content.slide` 會使用 `course.content` 的模型及其備援模型。有需求的插槽不會改用不符合需求的備援模型。

### 關閉某項能力

在它的插槽上寫 `null`。`video: null` 會對所有工作區關閉影片生成，並鎖定為關閉；`course.content.pbl: null` 只關閉 PBL 場景生成，`course.content` 的其他部分照常運作。對已關閉插槽的呼叫會立即失敗，媒體相關介面回傳 `403`，而不是改用其他廠商。

### 鎖定與瀏覽器設定

`openmaic.yml` 中 `slots` 下寫出的內容都會被**鎖定**：它對所有使用者生效，使用者在瀏覽器設定中為該插槽做的選擇不起作用。寫出的插槽也會涵蓋其下所有沒有自己指派的插槽，因此只寫 `llm` 就能固定所有對話呼叫，包括瀏覽器「課程模型配置」中的分步模型。要讓某個用途維持開放，只指派需要固定的插槽，不要指派它們的祖先。

每位使用者在瀏覽器中（**設定**）設定模型，瀏覽器會隨每個請求傳送這些選擇，包括 key：

- **Token Plan**：用一把 key 連接 Token Plan，它會填好方案涵蓋的各項能力的供應商。
- **模型服務**：每種能力一個分頁（語言模型、圖像生成、影片生成、語音合成、語音辨識、文件解析、網路搜尋），用於新增 key、自訂端點和模型，並選擇該能力使用的供應商。
- **課程模型配置**：在主模型之外，為每個生成步驟指定模型。

這些設定和 key 只儲存在瀏覽器中，伺服器端不儲存它們。瀏覽器會把透過舊版變數或 `server-providers.yml` 設定的供應商列為伺服器端設定，但不會列出 `openmaic.yml` 中的供應商，也不會標示被鎖定的插槽：部署指派的插槽會直接覆寫瀏覽器的選擇。

### 工作區設定 API

伺服器端還為每個工作區保存一份模型設定（`/api/model-config`），結構與 `openmaic.yml` 相同但沒有 `policy`；Web 端沒有對應的介面。它的指派排在 `openmaic.yml` 之後、瀏覽器選擇之前。工作區即[持久化文件](./deployment.mdx)中所說的擁有者（owner）：預設的 Docker Compose 部署（單使用者模式）只有一個工作區；多使用者部署中，每個已登入帳號各有一個工作區。

### 政策

```yaml
policy:
  allowWorkspaceProviders: false
```

`allowWorkspaceProviders`（預設 `true`）決定工作區設定 API 能否新增供應商；設為 `false` 時，工作區先前新增的供應商也不再使用。它不影響使用者在瀏覽器設定中填寫的 key：要固定某個插槽使用什麼，請在 `openmaic.yml` 中指派它。

### 金鑰與 OPENMAIC_SECRET_KEY

- `openmaic.yml` 中的 key 透過 `${VAR}` 來自環境變數，不會寫入資料庫，也不會傳送到瀏覽器。
- 透過工作區設定 API 儲存的 key 存放在資料庫中，使用實例金鑰 `OPENMAIC_SECRET_KEY` 以 AES-256-GCM 加密。在瀏覽器設定中填寫的 key 只儲存在該瀏覽器中，隨每個請求傳送；伺服器端不儲存它們。
- 未設定 `OPENMAIC_SECRET_KEY` 時，伺服器端會在首次使用時於 `data/instance-secret.key`（Docker Compose 中位於 `openmaic-data` 資料卷內）產生一把隨機金鑰，之後持續使用它。

請把這把金鑰和資料庫備份放在一起：金鑰遺失或更換後，先前儲存的 key 無法讀取，需要重新填寫（工作區設定 API 會標示這些 key）。多個實例共用同一個資料庫時，或在沒有持久化資料目錄的平台（例如 Vercel）上，請明確設定 `OPENMAIC_SECRET_KEY`；任何字串都可以，例如 `openssl rand -base64 32` 的輸出。

```bash
OPENMAIC_SECRET_KEY=...        # 透過工作區設定 API 儲存的 key 所使用的實例金鑰
OPENMAIC_CONFIG=/etc/openmaic/openmaic.yml   # 選填：openmaic.yml 的其他路徑
```

### 工作區設定 API 接受什麼

`openmaic.yml` 中的供應商可以是 schema 允許的任何內容。透過工作區設定 API 新增的供應商限制較多，因為其端點和 key 來自使用者：

- 不提供 Amazon Bedrock：它會使用伺服器端自己的 AWS 憑證簽署。
- 不能設定 `proxy`，也不能使用金鑰對（`credentials`）：AliDocMind 等使用金鑰對驗證的範本只能由部署設定。
- 只有提供對話能力的範本才能設定自訂 `baseUrl`，而且帶自訂端點的供應商只能用於對話插槽。URL 不能包含憑證、查詢字串或片段，而且必須解析到公網位址，除非伺服器端設定了 `ALLOW_LOCAL_NETWORKS=true`。對它的請求不會跟隨重新導向。
- 本機模型服務（Ollama、Lemonade）必須填寫自己的端點，不能使用範本預設的 `localhost`。
- 自架的媒體、搜尋和文件服務（VoxCPM2、FunASR、Lemonade 語音與圖像、ComfyUI、SearXNG、自架 MinerU）執行在伺服器端自己的網路中，只能由部署設定。
- 維運人員用舊版 `<CAP>_<VENDOR>_ENABLED=false` 變數關閉的供應商會被拒絕。
- 工作區不能宣告 `openmaic.yml` 已宣告過的供應商 ID。

如果希望使用者存取內網服務，請在 `openmaic.yml` 中宣告這些供應商。

### 來自瀏覽器和 API 呼叫端的請求

`/api/generate-classroom` 等無瀏覽器 API 呼叫會依呼叫端所在的工作區，透過與 Web 端相同的插槽解析模型；對於部署已指派的插槽，它們不需要 key。

瀏覽器透過請求標頭和請求本文欄位傳送它的選擇：`x-model`、`x-api-key`、`x-base-url`、`x-provider-type`、`x-model-routes`、`x-image-provider`、`x-image-model`、`x-video-provider`、`x-video-model`，以及語音、搜尋和文件介面中對應的請求本文欄位。只有當它們會影響的插槽在 `openmaic.yml` 和工作區設定中都沒有指派時才會生效；插槽一旦有指派，以設定為準；設為 `null` 的插槽無論請求寫了什麼都會拒絕。以這種方式傳送的端點會像使用者填寫的任何位址一樣被檢查：除非伺服器端設定了 `ALLOW_LOCAL_NETWORKS=true`，否則必須解析到公網位址。

### 從舊設定遷移

沒有 `openmaic.yml` 時，伺服器端會在啟動時轉換舊設定，記錄一則棄用提示，並為每個無法轉換的項目各記錄一則提示：

| 舊設定 | 轉換結果 |
| --- | --- |
| 供應商變數（`OPENAI_API_KEY`、`TTS_MINIMAX_API_KEY` 等）和 `server-providers.yml` | 部署供應商。供應商 ID 就是範本 ID，與舊的 provider ID 相同，只有網路搜尋的 MiniMax（`minimax-search`）、網路搜尋的豆包（`doubao-search`）和 Lemonade 圖像（`lemonade-image`）例外 |
| `<PREFIX>_MODELS` | 供應商的 `models` |
| `DEFAULT_MODEL` | `llm` 的指派，作為預設值（不鎖定），工作區設定和每位使用者的瀏覽器選擇都可以覆寫它。`agent` 插槽和以前一樣維持關閉 |
| `MODEL_FALLBACK` | `DEFAULT_MODEL` 的備援模型。沒有 `DEFAULT_MODEL` 時會被捨棄並給出提示 |
| 第一個設定的 TTS、ASR、圖像、影片和文件供應商，以及依舊優先順序選出的網路搜尋供應商 | 該能力的預設指派（圖像供應商由 `DEFAULT_IMAGE_PROVIDER` 指定） |
| `MODEL_ROUTES` | **不轉換。** 服務拒絕啟動（見下文） |
| `<CAP>_<VENDOR>_ENABLED=false` | 仍然有效：無論誰指派，該供應商都維持關閉 |

存在 `openmaic.yml` 時，`DEFAULT_MODEL`、`MODEL_FALLBACK` 和 `MODEL_ROUTES` 會被忽略，供應商變數和 `server-providers.yml` 也不再轉換為插槽指派，並會給出提示。它們設定的供應商仍作為伺服器端設定的供應商，供使用者在瀏覽器設定中選擇。`<CAP>_<VENDOR>_ENABLED=false` 仍然有效；要為所有人關閉某項能力，請改為把它的插槽設為 `null`。

**環境變數。** 遷移前：

```bash
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
DEFAULT_MODEL=openai:gpt-5.5
MODEL_FALLBACK=anthropic:claude-sonnet-4-6
TTS_MINIMAX_API_KEY=...
TAVILY_API_KEY=tvly-...
```

遷移後（key 仍留在環境變數中）：

```yaml title="openmaic.yml"
providers:
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}
  minimax-tts:
    preset: minimax-tts
    apiKey: ${TTS_MINIMAX_API_KEY}
  tavily:
    preset: tavily
    apiKey: ${TAVILY_API_KEY}

slots:
  llm:
    model: openai:gpt-5.5
    fallback: anthropic:claude-sonnet-4-6
  tts: minimax-tts
  webSearch: tavily
```

之後刪除 `DEFAULT_MODEL` 和 `MODEL_FALLBACK`。供應商變數可以保留，作為 `${VAR}` 引用的來源。與轉換得到的 `DEFAULT_MODEL` 不同，這裡寫出的 `llm` 是鎖定的；如果希望使用者在瀏覽器設定中自行選擇，就不要把它寫進 `slots`。另外，與轉換結果不同，`agent` 現在會沿用 `llm`：如需維持 Pro 智慧體關閉，請寫 `agent: null`。

**server-providers.yml。** 遷移前：

```yaml title="server-providers.yml"
providers:
  azure:
    apiKey: ...
    baseUrl: https://YOUR-RESOURCE.openai.azure.com/openai
    models: [my-deployment]
pdf:
  alidocmind:
    accessKeyId: ...
    accessKeySecret: ...
web-search:
  searxng:
    baseUrl: http://searxng:8080
```

遷移後：

```yaml title="openmaic.yml"
providers:
  azure:
    preset: azure
    apiKey: ${AZURE_OPENAI_API_KEY}
    baseUrl: https://YOUR-RESOURCE.openai.azure.com/openai
    models: [my-deployment]
  alidocmind:
    preset: alidocmind
    credentials:
      accessKeyId: ${ALIDOCMIND_ACCESS_KEY_ID}
      accessKeySecret: ${ALIDOCMIND_ACCESS_KEY_SECRET}
  searxng:
    preset: searxng
    baseUrl: http://searxng:8080

slots:
  llm: azure:my-deployment
  document: alidocmind
  webSearch: searxng
```

`server-providers.yml` 的每個區段都對應使用相應範本的供應商（`providers` → 對話範本，`tts`、`asr`、`pdf` → 文件，`image`、`video`、`web-search`），`accessKeyId`/`accessKeySecret` 移到 `credentials` 之下。

**MODEL_ROUTES。** 設定了 `MODEL_ROUTES` 但沒有 `openmaic.yml` 的服務不會啟動：

```text
MODEL_ROUTES does not carry over to the model configuration: write the per-stage models as slots in openmaic.yml (or the file named by OPENMAIC_CONFIG) and remove MODEL_ROUTES
```

依階段的路由與插槽並非一一對應，因此不會自動轉換。請把每條路由改寫成該階段所屬的插槽：

| `MODEL_ROUTES` 階段 | 插槽 |
| --- | --- |
| `web-search-query-rewrite` | `course.research` |
| `scene-outlines-stream` | `course.outline` |
| `agent-profiles` | `course.agents` |
| `scene-content` | `course.content` |
| `scene-content:slide`、`:quiz`、`:interactive`、`:pbl` | `course.content.slide`、`.quiz`、`.interactive`、`.pbl` |
| `scene-actions` | `course.actions` |
| `chat-adapter`、`quiz-grade`、`pbl-v2-runtime` 及其 `:instructor`、`:open-task`、`:evaluate`、`:simulator` 變體 | `classroom` |
| `generate-classroom` | `llm` |
| `maic-agent-driver` | `agent` |
| `conversation-title` | `agent.title` |

多個階段共用一個插槽時，為該插槽指定它們應共同使用的那個模型。路由中的 `thinking` 移到插槽的 `thinking`，`maic-agent-driver` 路由的 `api` 和 `contextWindow` 移到 `agent` 插槽。遷移前：

```bash
DEFAULT_MODEL=openai:gpt-5.5
MODEL_ROUTES='{"scene-outlines-stream":"anthropic:claude-sonnet-4-6","scene-content:slide":{"model":"openai:gpt-5.4","thinking":{"effort":"low"}},"maic-agent-driver":{"model":"openai:gpt-5.5","api":"openai-completions"}}'
```

遷移後：

```yaml title="openmaic.yml"
providers:
  openai:
    preset: openai
    apiKey: ${OPENAI_API_KEY}
  anthropic:
    preset: anthropic
    apiKey: ${ANTHROPIC_API_KEY}

slots:
  llm: openai:gpt-5.5
  course.outline: anthropic:claude-sonnet-4-6
  course.content.slide:
    model: openai:gpt-5.4
    thinking: { effort: low }
  agent:
    model: openai:gpt-5.5
    api: openai-completions
```

然後刪除 `MODEL_ROUTES`、`DEFAULT_MODEL` 和 `MODEL_FALLBACK`。

**Docker。** 把檔案掛載到應用程式旁邊，key 仍放在 `.env.local` 中：

```yaml
services:
  openmaic:
    volumes:
      - ./openmaic.yml:/app/openmaic.yml:ro
```

## ACCESS_CODE —— 全站存取密碼

對於共享部署（內部 demo、課堂），可以設定存取碼，訪客必須先輸入密碼才能看到應用程式：

```bash
ACCESS_CODE=your-secret-code
```

請使用足夠長的隨機值（至少 16 個字元），因為該密碼是保護部署的唯一金鑰。驗證通過後會在 HTTP-only cookie 中儲存一個簽名權杖，有效期 7 天，由伺服器端強制檢查，過期後需要重新驗證。只有在受信任的反向代理後設定 `TRUST_PROXY_HEADERS=true`（由代理覆寫 `x-forwarded-for` / `x-real-ip`）時才會限制驗證速率：依用戶端限制（每個用戶端 60 秒內 10 次），驗證成功會清除該用戶端的計數；沒有可信代理時應用程式無法將請求歸因到特定用戶端，因此完全不限流，保護取決於密碼的長度與隨機性。留空即可關閉此功能。

## 功能開關

功能開關的值可設為 `true` 或 `1`；除非另有說明，其他值都視為關閉。`NEXT_PUBLIC_*` 開關會在建置時編譯至用戶端，修改後需要重新建置：

```bash
# MAIC Editor（Pro 模式）
NEXT_PUBLIC_MAIC_EDITOR_ENABLED=true

# Pi 對話執行時預設開啟；取消下一行的註解可回復舊版鏈路
# NEXT_PUBLIC_PI_CHAT_ENABLED=false

# Pi 播放態中的 PPT 與互動頁課件引用（建置時開關；不影響編輯態引用）
NEXT_PUBLIC_COURSEWARE_REFERENCE_ENABLED=true

# 職業教育任務引擎（伺服器端開關）
OPENMAIC_ENABLE_VOCATIONAL=true

# 顯示職業教育實驗開關
NEXT_PUBLIC_SHOW_VOCATIONAL_TEST_UI=true

# 顯示影片匯出入口
NEXT_PUBLIC_ENABLE_VIDEO_EXPORT=true

# 顯示實驗性 PPTX 匯入入口
NEXT_PUBLIC_ENABLE_PPTX_IMPORT=true
```

Pi 對話執行時依賴模型的工具／函式呼叫能力。如果所選模型或 provider 不支援工具呼叫，請設定 `NEXT_PUBLIC_PI_CHAT_ENABLED=false`（或 `0`）並重新建置，以使用舊版對話鏈路。

使用 Docker Compose 時，`.env.local` 由 `env_file` 在執行時載入，不參與建置參數插值。請依下方指令明確傳入建置時設定並重新建置；只修改執行時環境不會改變已建置的用戶端與伺服器對話路徑。

```bash
NEXT_PUBLIC_PI_CHAT_ENABLED=false docker compose up -d --build openmaic
```

PPTX 匯入目前仍是實驗性入口，解析結果尚未完整整合至課堂資料流。以上 `NEXT_PUBLIC_*` 變數都是建置時開關；Docker 部署還需要透過 build args 傳入，不能只寫在容器執行時環境變數中。

## 其他伺服器端選項

以下伺服器端選項也可以透過環境變數設定：

```bash
PARALLEL_SCENE_CONCURRENCY=3

```

## 舊版供應商環境變數

這些變數和 `server-providers.yml` 是早期版本的設定方式。在沒有 `openmaic.yml` 時它們仍然有效（見[從舊設定遷移](#從舊設定遷移)），但已棄用。使用 `openmaic.yml` 時，把它們作為 `${VAR}` 引用的來源；它們設定的供應商也仍以伺服器端設定的形式供瀏覽器設定使用。`DEFAULT_MODEL` 和 `MODEL_FALLBACK` 請見遷移一節；`MODEL_ROUTES` 已不再讀取。

### LLM 供應商

雲端供應商通常使用三個環境變數：API key、base URL 和 model 清單。API key 通常為必填，base URL 和 model 清單則為選填；Azure OpenAI 需要設定資源 endpoint，Ollama 和 Lemonade 不需要 API key。

```bash
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=                # 選填的 base URL 覆寫值
OPENAI_MODELS=                  # 選填的模型白名單（以逗號分隔）
```

支援的 provider 字首：

| 字首               | 供應商                               |
| ------------------ | ------------------------------------ |
| `OPENAI_`          | OpenAI                               |
| `AZURE_OPENAI_`    | Azure OpenAI                         |
| `ANTHROPIC_`       | Anthropic                            |
| `GOOGLE_`          | Google Gemini                        |
| `DEEPSEEK_`        | DeepSeek                             |
| `QWEN_`            | Alibaba Qwen                         |
| `KIMI_`            | Moonshot Kimi                        |
| `MINIMAX_`         | MiniMax（預設用 Anthropic 相容端點） |
| `GLM_`             | Zhipu GLM                            |
| `SILICONFLOW_`     | SiliconFlow                          |
| `DOUBAO_`          | Doubao（ByteDance）                  |
| `OPENROUTER_`      | OpenRouter                           |
| `GROK_`            | xAI Grok                             |
| `TENCENT_`         | Tencent Hunyuan                      |
| `TENCENT_HUNYUAN_` | Tencent Hunyuan（別名）              |
| `XIAOMI_`          | Xiaomi MiMo                          |
| `MIMO_`            | Xiaomi MiMo（別名）                  |
| `OLLAMA_`          | Ollama（本機）                       |
| `LEMONADE_`        | Lemonade（本機）                     |

Azure OpenAI 使用 deployment name 作為模型 ID：

```bash
AZURE_OPENAI_API_KEY=...
AZURE_OPENAI_BASE_URL=https://YOUR-RESOURCE.openai.azure.com/openai
AZURE_OPENAI_MODELS=your-deployment-name
```

如需連接其他 OpenAI 相容的 LLM 服務，請在 **設定 → 模型服務 → 語言模型** 中新增自訂供應商，或在 `openmaic.yml` 中宣告一個帶 `baseUrl` 和 `models` 的 `openai-compatible` 供應商。

### 本機模型（Ollama 和 Lemonade）

Ollama 和 Lemonade 不需要 API key；本機服務的 base URL 應寫在伺服器端設定中，以通過 SSRF 驗證：

```bash
OLLAMA_BASE_URL=http://localhost:11434/v1
# LEMONADE_BASE_URL=http://localhost:13305/v1
```

如需限制可用模型，可使用 `OLLAMA_MODELS` 或 `LEMONADE_MODELS` 指定模型白名單。

### TTS 供應商

伺服器端 TTS 供應商使用 `TTS_<PROVIDER>_API_KEY`，並可選擇設定 `TTS_<PROVIDER>_BASE_URL`。

```bash
# Doubao TTS（Volcengine Seed-TTS，原生 MP3）
TTS_DOUBAO_API_KEY=appId:accessKey
TTS_DOUBAO_BASE_URL=       # 選填覆寫值

# Qwen TTS
TTS_QWEN_API_KEY=
TTS_QWEN_BASE_URL=         # 選填覆寫值

# 任何 OpenAI 相容的 TTS 端點
TTS_OPENAI_API_KEY=
TTS_OPENAI_BASE_URL=

# VoxCPM2（自託管 TTS，支援聲音複製，詳見 VoxCPM2 獨立頁面）
TTS_VOXCPM_BASE_URL=http://localhost:8000
```

支援的 TTS 字首包括 `TTS_OPENAI_`、`TTS_AZURE_`、`TTS_GLM_`、`TTS_QWEN_`、`TTS_MINIMAX_`、`TTS_DOUBAO_`、`TTS_ELEVENLABS_`、`TTS_VOXCPM_` 和 `TTS_LEMONADE_`。本機 Lemonade TTS 和 VoxCPM2 不需要 API key。瀏覽器原生 TTS 不需要伺服器端設定。

管理員可以使用 `TTS_<PROVIDER>_ENABLED=false` 在伺服器端強制關閉某個 TTS 供應商。VoxCPM2（自託管 TTS + 聲音複製）請見獨立的 [VoxCPM2](./voxcpm.mdx) 章節。

使用者也可以在 **設定 → 模型服務 → 語音合成** 中新增自訂 OpenAI 相容 TTS 供應商，填寫 Base URL、模型和音色；它儲存在該瀏覽器中。要為所有人設定，請在 `openmaic.yml` 中宣告一個帶該 `baseUrl` 的 `openai-tts` 供應商，並把 `tts` 插槽指派給它。

### ASR（語音轉文字）

```bash
# OpenAI Whisper
ASR_OPENAI_API_KEY=
ASR_OPENAI_BASE_URL=       # 選填覆寫值

# Qwen ASR
ASR_QWEN_API_KEY=
ASR_QWEN_BASE_URL=         # 選填覆寫值

# Azure ASR
ASR_AZURE_API_KEY=
ASR_AZURE_BASE_URL=https://{region}.api.cognitive.microsoft.com

# FunASR（本機，不需要 key）
ASR_FUNASR_BASE_URL=http://localhost:8000/v1

# Lemonade ASR（本機，不需要 key）
ASR_LEMONADE_BASE_URL=http://localhost:13305/v1
```

使用 `funasr-server --device cuda` 啟動 OpenAI 相容服務。它在 `/v1/audio/transcriptions` 接收 WAV，並可在模型選擇器中使用 SenseVoiceSmall、Paraformer 和 Fun-ASR-Nano。

瀏覽器原生 ASR 不需要伺服器端設定。

使用者也可以在 **設定 → 模型服務 → 語音辨識** 中新增自訂 OpenAI 相容 ASR 供應商，填寫 Base URL、模型和支援的語言；它儲存在該瀏覽器中。要為所有人設定，請在 `openmaic.yml` 中以 `openai-whisper` 範本和它的 `baseUrl` 宣告該服務，並把 `asr` 插槽指派給它：

```yaml title="openmaic.yml"
providers:
  my-asr:
    preset: openai-whisper
    apiKey: ${MY_ASR_API_KEY}
    baseUrl: https://asr.example.com/v1

slots:
  asr: my-asr:whisper-1
```

### 圖像生成供應商

圖像生成供應商使用 `IMAGE_<PROVIDER>_API_KEY`，可選 `IMAGE_<PROVIDER>_BASE_URL`。支援的字首包括：

`IMAGE_OPENAI_`、`IMAGE_SEEDREAM_`、`IMAGE_QWEN_IMAGE_`、`IMAGE_NANO_BANANA_`、`IMAGE_MINIMAX_`、`IMAGE_GROK_` 和 `IMAGE_LEMONADE_`。

Lemonade 是本機服務，不需要 key：

```bash
IMAGE_LEMONADE_BASE_URL=http://localhost:13305/v1
```

ComfyUI Image 不需要 API key，預設連接 `http://localhost:8188`。使用者可以在 **設定 → 模型服務 → 圖像生成** 中填寫 ComfyUI Base URL；在那裡填寫的位址會像使用者填寫的任何端點一樣被檢查，因此執行在主機或內網中的 ComfyUI 還需要伺服器端設定 `ALLOW_LOCAL_NETWORKS=true`。要為所有人設定，請在 `openmaic.yml` 中宣告它，並把 `image` 插槽指派給它：

```yaml title="openmaic.yml"
providers:
  comfyui:
    preset: comfyui-image
    baseUrl: http://host.docker.internal:8188

slots:
  image: comfyui
```

把以 API 格式匯出的工作流程 JSON 放到 OpenMAIC 的 `public/` 目錄中，檔名需符合 `comfyui-*.json` 或包含 `workflow`；設定頁會自動偵測這些檔案並作為工作流程提供。使用 Docker 時，請在建置映像檔前加入工作流程，或把單一工作流程檔案掛載到容器內的 `/app/public/`。在 `openmaic.yml` 中宣告時，執行在主機或內網中的 ComfyUI 不需要 `ALLOW_LOCAL_NETWORKS`。

### 影片生成供應商

影片生成供應商使用 `VIDEO_<PROVIDER>_API_KEY`，可選 `VIDEO_<PROVIDER>_BASE_URL`。支援的字首包括：

`VIDEO_SEEDANCE_`、`VIDEO_KLING_`、`VIDEO_VEO_`、`VIDEO_SORA_`、`VIDEO_MINIMAX_`、`VIDEO_GROK_` 和 `VIDEO_HAPPYHORSE_`。

### 文件和媒體解析

課程材料的實際格式取決於所選解析器。目前支援文字、PDF、Office 文件、圖片以及部分音訊與影片格式；不同 provider 支援的格式和功能各不相同。

```bash
# MinerU 自託管
PDF_MINERU_BASE_URL=http://localhost:8888

# MinerU 自託管的可選後端
PDF_MINERU_BACKEND=pipeline

# MinerU Cloud
PDF_MINERU_CLOUD_API_KEY=
PDF_MINERU_CLOUD_BASE_URL=https://mineru.net/api/v4

# AliDocMind（使用 Alibaba Cloud AccessKey，而不是獨立的 API key）
ALIDOCMIND_ACCESS_KEY_ID=
ALIDOCMIND_ACCESS_KEY_SECRET=
ALIDOCMIND_BASE_URL=       # 選填覆寫值
```

`unpdf` 內建於 OpenMAIC，可用於基礎 PDF 解析。Office 文件、圖片和需要 OCR、表格、公式或版面分析的材料，應選擇相容的 MinerU 或 AliDocMind provider。

AliDocMind 的文件解析支援 PDF、DOCX、PPTX、XLSX，以及 PNG、JPG/JPEG、BMP、GIF。目前音訊與影片材料僅支援透過 AliDocMind 解析：影片格式為 MP4、MOV、AVI、MKV、WMV，音訊格式為 MP3、WAV、AAC；不支援 M4A。

### 聯網搜尋

設定 Tavily、Exa、Bocha、Brave、Baidu、SearXNG 或 MiniMax：

```bash
TAVILY_API_KEY=
TAVILY_BASE_URL=           # 選填覆寫值

EXA_API_KEY=
EXA_BASE_URL=https://api.exa.ai  # 選填覆寫值

BOCHA_API_KEY=
BOCHA_BASE_URL=            # 選填覆寫值

BAIDU_API_KEY=
BAIDU_BASE_URL=https://qianfan.baidubce.com  # 選填覆寫值

# 自託管 SearXNG，不需要 API key
SEARXNG_BASE_URL=

WEB_SEARCH_MINIMAX_API_KEY=
WEB_SEARCH_MINIMAX_BASE_URL=https://api.minimaxi.com  # 選填覆寫值
```

Brave 和 SearXNG 不需要 API key。前端可以在每次生成時選擇是否啟用搜尋；在 `openmaic.yml` 中寫 `webSearch: null` 會為所有人關閉它。Grok 的聯網搜尋透過 Grok LLM 的搜尋工具提供，不是獨立的聯網搜尋 provider。

### server-providers.yml

已由 `openmaic.yml` 取代。兩者同時存在時，只有 `openmaic.yml` 用於設定模型。

除了環境變數，也可以將程式碼中已註冊 provider 的設定放在專案根目錄下的 `server-providers.yml` 檔案中。伺服器啟動時會載入此檔案，其結構與環境變數分類相對應：

```yaml title="server-providers.yml"
providers:
  openai:
    apiKey: sk-...
    baseUrl: https://api.openai.com/v1
    models:
      - gpt-5.5
  anthropic:
    apiKey: sk-ant-...

tts:
  doubao-tts:
    apiKey: appId:accessKey

asr:
  openai-whisper:
    apiKey: sk-...

pdf:
  mineru:
    baseUrl: http://localhost:8888
  alidocmind:
    accessKeyId: your-access-key-id
    accessKeySecret: your-access-key-secret

image:
  seedream:
    apiKey: ...

video:
  seedance:
    apiKey: ...

web-search:
  tavily:
    apiKey: tvly-...
  exa:
    apiKey: ...
  searxng:
    baseUrl: http://localhost:8080
```

環境變數會逐欄位覆蓋 YAML 中的同名 provider 設定。鍵名必須使用程式碼中已註冊的 provider ID，例如 `openai`、`doubao-tts`、`openai-whisper`、`mineru`、`alidocmind`、`seedream`、`seedance`、`exa`、`tavily` 或 `searxng`；未知 ID 不能在這裡註冊為自訂 LLM provider。
